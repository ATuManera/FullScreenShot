# FullScreenShot

> Privacy-first full-page screenshot browser extension powered by Rust
> and WebAssembly. Capture visible pages, complete pages and scrollable
> regions, with local export to PNG, PDF and Markdown.

**Status: pre-alpha (P0 — Foundation).** Capture functionality is not
implemented yet; see [Roadmap](#roadmap).

## What is FullScreenShot

FullScreenShot is an open-source browser extension for Chrome, Edge,
and Safari that captures full web pages — visible viewport, entire
scrollable pages, or a specific scrollable container — and exports the
result as PNG, PDF, or semantic Markdown. Everything runs locally in
your browser: no servers, no accounts, no telemetry.

## Features (target scope)

- Capture Visible / Capture Full Page / Capture Selected Scroll Area
- Export to PNG (lossless), PDF (paginated, with a searchable text
  layer), and Markdown (from the DOM, not OCR)
- Handles fractional device-pixel-ratio, browser zoom, sticky/fixed
  headers, and lazy-loaded content
- Manifest V3, minimal permissions, no `<all_urls>`, no
  `chrome.debugger`

## The PDF export

A FullScreenShot PDF is a hybrid: it looks like the capture and behaves
like a document.

- **The picture is the capture.** Each page carries the same raster the
  PNG export would have produced — nothing is re-rendered, and no print
  stylesheet gets a say in what the file looks like.
- **The text comes from the DOM.** Over that raster goes an invisible
  text layer built from the page's own text geometry, so the PDF can be
  searched, selected and copied. This is not OCR: the text is read from
  the document, not guessed from pixels.
- **Links stay links.** Rendered `http`/`https` hyperlinks become
  clickable PDF annotations, including links that wrap across lines.
  Other schemes (`javascript:`, `data:`, `blob:`, `file:`) are dropped.
- **Everything stays local.** No network request, no upload, no remote
  font — the embedded font is generated by the exporter itself.

Known limits, stated plainly:

- Text drawn inside images, `<canvas>` or WebGL stays part of the
  picture only. There is no DOM to read it from.
- Content in iframes is captured visually but is not in the text layer.
- This is a searchable PDF, **not** a tagged PDF: there is no structure
  tree, so it is not PDF/UA and is not described as an accessible PDF.
- Bidirectional text is written in document order, without visual
  reordering.

See [ADR-0007](docs/architecture/ADR-0007-hybrid-pdf-text-layer.md) for
why it is built this way.

## The Markdown export

Markdown comes from the DOM, never from OCR, and it represents what the
page actually shows.

- **Hidden text stays out.** Content the browser does not render —
  `display:none`, `visibility:hidden`/`collapse`, `opacity:0`, the
  `hidden` attribute, `content-visibility:hidden`, and the clipped
  one-pixel box screen-reader-only text uses — is not exported.
  `aria-hidden` content *is* exported, because it is still on screen.
- **Prose stays prose.** A page's own HTML source indentation is
  collapsed the way CSS collapses it, so a paragraph never arrives as
  an indented code block. Preformatted content keeps its whitespace
  byte for byte, decided by computed `white-space` rather than tag
  name.
- **Links travel.** Relative hrefs are exported as the absolute URLs
  the browser resolved them to, so the file still works once it leaves
  the site. `javascript:` and `data:` links keep their text and lose
  their link.

## Architecture

```text
Chrome / Edge / Safari
        │
        ▼
Minimal WebExtension adapter (JavaScript / TypeScript)
        │
        ▼
Rust / WebAssembly Core
        (geometry, capture planning, stitching, PNG, PDF, Markdown)
```

The browser-dependent shell is intentionally small and auditable; all
non-trivial logic (geometry, tiling, compositing, encoding, Markdown
generation) lives in Rust, compiled to WebAssembly. See
`docs/architecture/` for the Architecture Decision Records behind
these choices.

## Installation

### From source (current state — no store listing yet)

```bash
git clone https://github.com/ATuManera/FullScreenShot
cd FullScreenShot
rustup target add wasm32-unknown-unknown
cargo xtask build
```

**Chrome:** open `chrome://extensions`, enable Developer mode, "Load
unpacked", select `dist/chromium/` (built by `browser/chromium/build.sh`).

**Edge:** open `edge://extensions`, enable Developer mode, "Load
unpacked", select `dist/chromium/`.

**Safari:** run `cargo xtask package safari` on a Mac with full Xcode
installed (the Command Line Tools alone are not enough) to generate an
Xcode project via `xcrun safari-web-extension-converter`, then open it
in Xcode to build/sign/run. See `browser/safari/README.md` for exactly
what is and isn't verified about Safari compatibility.

## Privacy & Security

See `PRIVACY.md` and `SECURITY.md`. In short: 100% local processing,
no telemetry, no analytics, no cloud, no account, no remote code.

## Limitations

Pre-alpha: capture, export, and Safari support are not implemented
yet. Some internal browser pages cannot be captured by any extension
regardless of permissions (browser security restriction) — FullScreenShot
will report this clearly rather than silently fail.

## Design inspiration

FullScreenShot's functional scope was informed by studying
[mrcoles/full-page-screen-capture-chrome-extension](https://github.com/mrcoles/full-page-screen-capture-chrome-extension)
as a reference for known full-page-capture problems (DPR handling,
sticky elements, seams). FullScreenShot is an independent
implementation with a different architecture (Rust/WASM core, Manifest
V3, streaming compositor) and does not reuse its code or assets.
